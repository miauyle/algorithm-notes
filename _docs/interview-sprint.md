这份笔记的目标不是顺序刷完 147 道题，而是尽快恢复 **识别模式 → 讲清思路 → 稳定编码 → 检查边界** 的能力。

如果时间有限，优先级按下面执行：

1. 先过 **Core 32**，保证主要模式都有一个能独立写出的锚点；
2. 再用 **Pattern Extension 12** 检查是否真的理解模式，而不是只记住某一道题；
3. B / C 题只在对应模式仍不稳、或实际面试暴露缺口时补；
4. 同一道题重复独立写，比继续扩题量更重要。

快速识别模式时先看[算法面试速查表](cheat-sheet.md)，需要理解“为什么适用”时再看[题型识别与解题套路](pattern-guide.md)。

对 Core 32 的要求不是“看懂”，而是至少能做到：

- 30～60 秒说出为什么选这个模式；
- 先定义指针、递归返回值或 DP 状态，再开始写代码；
- 独立写出主实现；
- 手推一个普通输入和一个边界输入；
- 说清时间复杂度和辅助空间。

## 3 天极速恢复

适合已经刷过这些题、只是手感下降时。

| 天 | 主线 | 建议 |
| --- | --- | --- |
| Day 1 | 数组 / 窗口 / 前缀 / 二分 / 链表 | Core 32 前半；每题只看题意，先口述再写 |
| Day 2 | 栈 / 堆 / 树 | 重点练单调结构、双堆、LRU、树递归返回值 |
| Day 3 | 图 / 回溯 / 贪心 / DP | 重点练 BFS 层次、回溯撤销、DP 状态定义 |

三天模式下不要追求“补完所有 B 题”。卡住超过 20～30 分钟就读推导，随后合上文档重新写一次。

## 7 天主线

| 天 | 内容 |
| --- | --- |
| Day 1 | 数组、哈希、双指针 |
| Day 2 | 滑动窗口、前缀和、二分 |
| Day 3 | 链表、栈、单调结构 |
| Day 4 | 堆、LRU、二叉树 / BST |
| Day 5 | 图、BFS / DFS、拓扑、回溯 |
| Day 6 | 贪心、区间、动态规划 |
| Day 7 | Core 32 随机抽题 + Pattern Extension 薄弱项 |

每天结束只记录三类错误：

1. **识别错**：没有看出可利用的性质；
2. **状态错**：指针 / 递归返回值 / DP 定义不清；
3. **实现错**：边界、更新顺序、撤销、下标等。

不要抄完整答案到错题表。

## 一道题怎样算真正恢复

沿用附录中的 0～3 自测标准：

- **0 没思路**：不知道从哪里开始；
- **1 看懂**：讲解能看懂，但独立写不出；
- **2 能写**：实现基本正确，但理由或边界说不完整；
- **3 能面试表达**：能识别、解释、编码、测试并分析复杂度。

冲刺阶段的停止条件：

- Core 32 尽量达到 3；
- Extension 12 至少达到 2，常见模式尽量达到 3；
- C 类题不因为“没刷完”而阻塞投递。

## 面试前一天

只做压缩，不再学新东西：

1. 10～15 分钟扫[算法面试速查表](cheat-sheet.md)；
2. 随机抽 6～8 道 Core 题，只口述模式、状态和边界；
3. 独立写 2～3 道自己最容易卡住的题；
4. 看自己的错误记录，不通读 147 道正文。

真正需要带进面试的是少量稳定的判断问题：

> 连续区间为什么能滑？二分为什么能丢一半？栈里保存的是什么？DFS 返回给父节点什么？BFS 为什么第一次到达就是最短？回溯撤销什么？DP 状态到底表示什么？

这些问题能答清楚，比继续扩题量更有价值。
